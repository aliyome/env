# 台本（script.json）の形式

雛形は `<skill>/assets/script.example.json`。`build_video.py` は、ここに書いた決まりから外れた文や項目を `warning:` で知らせる（止まらずに、出せる形に直して続ける）。

## 全体

- `voice`: `speech serve` に登録した**話者名（文字列）**。既定は `"narrator"`。
- `readings`: 字幕はそのまま、音声だけ読み替える辞書（`{"表記": "よみ"}`）。スキル同梱の辞書・ユーザーの辞書とまとめて使われ、同じ語は台本が優先する（SKILL.md の手順6）。
- `scenes`: シーンの配列。各シーンは `id`・`title`・`sentences`・`visual` を持つ。

## シーン

- `id`: 小文字の英数字とハイフンだけ（例 `s01-opening`）。ファイル名と要素の ID に使うので、ほかの文字があると build_video.py が止まる。
- `title`: 画面の左上に出る見出し。
- `sentences`: 1要素＝字幕1枚＝音声1本。**1文36字以内**（半角は0.5字で数える）。字幕は約36字で折り返し、2行になると図の下端に重なる。長い文は2つに分ける。文は「。」まで書く。字幕では文末の「。」を表示しない（テロップの慣習に合わせる。音声には影響しない）。
- `visual`: 図の指定。下のレイアウトと部品で組むか、自作の図（`component`）にする。

## visual

- `at`: 何番目の文（0始まり）で出すか。範囲外だと warning を出して端の文に寄せる。
- `until`: その文の後に消す（`at` 以上、最後の文以下）。
- `layout`:
  - `grid`: カードを `cols` 列で並べ、画面の高さいっぱいに広げる。
  - `steps`: `step` を矢印でつなぐ横一列＋下にカード。`steps` だけだと下が空くので、補足の `card` を足すとよい。
  - `split`: 左に画像かコード、右にカード。右列は「card 2枚＋短い note」程度までにする（多いと字幕に食い込む）。
  - `stack`: 上に画像かコードを横幅いっぱいに、下にカードと note を横一列。
  - `img` と `code` はどのレイアウトでも出るが、大きく見せたいときは `split` か `stack` にする。
- 画像の形でレイアウトを選ぶ。
  - 縦長・正方形に近い画像は `split`。横長の画像も、まず `split` でよい（左の列が画像の縦横比に合わせて広がり、高さいっぱいに表示される）。
  - 横が縦の3倍を超える帯状の画像は `stack` にする（`split` と書いても build_video.py が `stack` に切り替える）。`stack` は下のカードが画像の高さを削るので、16:9 前後の画像ではかえって小さくなる。
  - 文字の多い画面キャプチャや書類は、レイアウトを選ぶ前に、話に要る部分だけを切り出す。
- `note` の位置は `items` の並び順で決まる。ほかのどの項目よりも前に書いた `note` は上（`split` では右列の上）に、それ以外の `note` は下に出る。最初の文で用語の説明を出し、カードはあとから出す、というときは `note` を先頭に書く。
- `kind`:
  - `card`: 見出し（`head`）＋本文（`body`）。本文の改行は JSON で `\n`。
  - `big`: 大きな数字。`value` の数字は0から数え上がる。年号など数え上げが不自然なときは `"count": false`。
  - `step`: 手順の1段。
  - `note`: 横長の帯。
  - `img`: `src` はプロジェクトからの相対パス（例 `assets/shots/x.png`）。`source` に出典。
  - `code`: `head` に「リポジトリ/パス:行」、`body` にコード本文（改行は JSON で `\n`）。文字の大きさは、コードが置かれる枠（レイアウトで決まる）の幅と高さに合わせて24〜34pxで自動で決まる。24pxでも収まらない長い行は折り返して warning を出すので、行を短くするか、出力なら列を削る。24pxでも下が切れるときも warning を出すので、行を減らす。書き出し時に Pygments で色が付く。言語は `lang`（`typescript`・`python`・`ruby` など Pygments の名前）で指定し、無ければ `head` の拡張子から推定し、推定できなければ色を付けない。
- `tone`: `blue`／`purple`／`green`／`orange`／`red`／`pink`／`gray`（色の中身は theme.css）。強調の色は `blue` だけで、ほかはすべて無彩色になる。`blue` は1シーンに1か所程度、いちばん伝えたい項目に付ける。
- コードを見せるシーンは、字幕と `card` で「何をしているか」を言葉で言い、識別子（関数名・変数名）を主語にしない。コードは裏付けとして横に置く。
- 手順の矢印は「順番があるもの」だけに使う。並列なもの（例: 東京・大阪・福岡）は `grid` にする。

## 自作の図（component）

図の種類が上の部品で足りないとき（時間軸、対応表、注釈付きの書類など）に使う。

- `visual` を `{"component": "<名前>"}` にし、プロジェクトに `custom/<名前>.html` を置く。
- 中身は図の HTML と `<script>`。script の中では `tl`（そのシーンのタイムライン）、`S`（各文の開始秒の配列）、`E`（各文の終了秒の配列）が使える。例 `tl.fromTo("#box", {opacity: 0, y: 24}, {opacity: 1, y: 0, duration: 0.6, ease: "expo.out"}, S[1]);`
- 色やフォントは theme.css の変数（`var(--text)` など）か `tone-*` クラスを使う。
- **別の動画で使い回すときは、文の数と順番を元の台本と同じにする**（図の出るタイミングが文の番号に結びついているため）。
